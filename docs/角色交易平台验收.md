# SourX 角色交易平台设计与验收

更新：2026-10-31。分支：`feature/v1.0.0`。

## 产品结构

旧版把商品、卖家心跳、买家任务、运营结算放在一张页面内，浏览器甚至持有三种角色的 ID。新版采用真实账户登录，服务端校验角色和资源归属，分别进入以下工作台。

| 身份 | 页面 | 可以执行的操作 |
| --- | --- | --- |
| 买家 | 概览、算力市场、商品详情、我的订单、订单详情、任务空间、账单、账户与安全 | 筛选商品、创建订单、沙箱支付、取消待支付订单、提交/取消自己的任务、结束自己的租约 |
| 卖家 | 经营概览、设备节点、商品管理、租出订单、订单详情、收益结算、账户与安全 | 为自己的设备生成接入码、暂停/恢复接单、创建/修改商品、上下架已审核商品、查看自己的订单与收益 |
| 运营 | 商品审核、订单管理、操作审计、账户与安全 | 审核商品、结算已完成订单、查询审计 |

各菜单进入独立 URL，刷新深链接后仍能加载。未知页面显示明确提示。越权路径显示无权访问，后端同时拒绝跨角色或跨账号调用。

## 视觉与交互

- 深蓝导航 `#101D32` 与浅灰背景 `#F5F7FA` 区分工作台和业务内容。
- 交易操作使用蓝色 `#365DE7`，正文 `#1D2C42`，辅助信息 `#76849A`，可用状态绿色 `#219C7A`。
- 字体角色：Avenir Next / 苹方标题、苹方正文、SF Mono 标识。
- 市场使用真实 API 的 GPU 配置卡片，GPU 插画由 CSS 绘制，无外部字体与图片依赖。
- 订单使用列表、详情、费用明细和履约时间线。支付、取消和结束租约均需确认。
- 表单包含验证、加载、失败、空态。弹窗支持 Escape、焦点约束及关闭后恢复焦点。
- 手机采用抽屉菜单，表格在容器内滚动，不挤压整个页面。

## 接口和权限

- `GET /v1/me` 返回当前已认证账户和角色。
- `GET /v1/config` 返回当前环境能力；仅本地模式显示样例邮箱，不返回任何身份 token。
- `GET /v1/catalog[/:id]` 返回可公开的 GPU 商品配置，不返回节点指纹、物理 UUID、Agent 凭证或 sandbox 信息。
- `/v1/buyer/*`、`/v1/provider/*`、`/v1/operator/*` 统一在服务端校验角色。
- 买家订单按 buyerId 过滤，卖家订单通过 Listing 的 providerId 过滤。
- 卖家订单响应不包含买家任务命令、输入内容或登录信息。
- 前端使用 Bearer 会话和 refresh 轮换，删除旧的开发身份头和全平台 Demo 概览。
- 浏览器只为自己的订单临时取得 capability，任务提交沿用 Gateway 所有权、租约、镜像白名单校验；capability 最长 15 分钟，不能超过租约到期时间。

## 交易行为

1. 买家选择商品和时长，确认访问规则，服务端重新计算报价并锁定 GPU 15 分钟。
2. 本地测试支付仅在 `DEMO_MODE=true` 可用；重复支付返回同一租约，不能重复分配。
3. 任务空间只展示当前买家的有效租约和任务。
4. 买家结束租约：取消任务、撤销 token、销毁 sandbox、清理 artifact、释放 GPU。本地模式由平台执行结算，买家不调用运营权限接口。
5. 结算中卖家应收为有效计量的算力金额，平台服务费在买家侧另计 5%。`chargedAmountMinor + releasedAmountMinor = order.totalAmountMinor`，未用授权金额单独记账。
6. 卖家编辑报价后商品回到待审核，运营通过后才可上架；历史订单保持原报价。
7. 暂停接单只影响新订单，正在运行的租约继续履约；Agent 心跳不能意外解除暂停状态。
8. 本地 worker 每 30 秒生成样例节点的模拟计量，租约到期回收权限。它不执行 GPU 任务。

## 数据与部署

Compose 设置 `DATA_FILE=/app/data/state.json` 并挂载命名卷 `sourx-data`。账户密码哈希、会话、节点、商品、订单、支付、租约、任务、计量、账本、Agent 凭证哈希与一次性接入码在请求变更后写入临时文件并原子替换；数据文件权限 0600，目录 0700。重启恢复，不重复初始化样例数据。

这是单实例的本地持久化方案；横向扩容或生产环境应使用数据库事务、队列、对象存储和独立密钥管理。运行时、支付与真实 GPU Agent 尚未接入，不宣称已完成生产上线。

## 验收

```bash
pnpm check
docker compose config --quiet
docker compose up --build -d
pnpm test:e2e
```

`tests/portal.test.ts` 覆盖跨角色/跨账号拒绝、卖家数据隔离、完整交易、重复支付、商品审核、历史报价、本地能力关闭和重启恢复。原有安全/计费/Agent 测试继续运行。

`tests/e2e/platform.spec.ts` 用本机 Chrome 验证买家市场、筛选、下单、支付、任务、结束结算；验证卖家菜单、节点暂停恢复、商品编辑与运营审核；检查 390 px 手机布局。截图写入本地 `artifacts/`，不提交 Git。

`tests/frontend-auth.test.ts` 验证并发请求只轮换一次会话、延迟返回的旧请求不能恢复退出的会话，以及切换账号时旧刷新不能覆盖或清除新账号。退出、登录时清除上一账号的提示。

本次验证：构建通过，11 个测试文件共 39 个用例通过，2 个 Chrome 端到端用例通过；实际重启 Docker 容器后，原会话可继续使用、原订单保留。手机截图等待抽屉收起后生成，并检查菜单点击后自动关闭。

后续 agent 开发应保留这些路由和 DTO 隔离，不能通过向浏览器返回其他身份的 token 来实现角色切换。新增功能需同时检查菜单、路由与服务端权限。
